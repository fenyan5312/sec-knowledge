AI Agent 自动化渗透测试

仅记录一些个人思路和看法

什么场景下使用 AI 进行自动化渗透？​

现在市面上很多 Skill 通过调用 nuclei、dirsearch、ffuf、nmap 等安全工具，进行一键化渗透测试，但在我看来，这类高重复度的工作完全可以交给自动化编排来做，结果更准更靠谱，没必要让 AI 来思考调用并等待结果，意义不大。

我认为让 AI 进行自动化渗透，应该把核心能力放在数据包分析、JS 代码分析这类需要思考的事上效果最好。AI 的深度思考和发散能力很强，又有充足的安全知识积累，用来做流量解析和脚本层面的安全测试，更容易挖到有价值的漏洞，实际收益会更高。本文也主要以这种方式进行探索。

AI 自动化渗透测试分类​

基于场景分析和传统漏扫的分类，我给 AI 自动化渗透也分为了 2 类（两类互补，不冲突）：

AI主动渗透（类似 AWVS）：输入目标站点，AI 驱动浏览器自动爬取接口并执行探测，输出安全报告。

  • ✅ 自动化程度高，输入目标 URL 即可启动全流程测试
  • ✅ 主动爬取接口与页面，可覆盖未被流量触达的资产盲区
  • ❌ 对强交互、鉴权复杂的前端场景，爬虫覆盖度有限

AI被动渗透（类似 xray）：通过 MCP 等通道获取抓包流量，AI 基于流量完成漏洞分析并执行测试，输出安全报告。

  • ✅ 仅基于已有流量分析，可严格限制测试的范围
  • ❌ 依赖前置流量采集环节，无法独立完成全链路测试

被动扫描需要人为抓取流量再提供给 AI 分析，建议使用 yakit 抓流量，再开放 yakit 的 MCP 能力给 AI 调用获取数据包分析。

后续的理念内容同时适配两种自动渗透方式。

设计理念&遵循规则​

因为 AI 本身具有非常丰富的渗透测试专业知识（如SQLI、SSRF、IDOR、LFI 等），过度指导反而会挤占上下文、限制推理空间，因此我们尽量的不要限制 AI 测试的思路，不需要告诉它 SQL 注入怎么测、越权怎么测，而是要告诉它测试的注意事项、报告标准等。

如果不是常见的测试思路，那么可以作为专项 Skill 让 AI 参考。

参考各种文章、日常实际需求，整理出 AI Agent 在渗透测试需要遵循要求如下：

  1. 测试日志留存，包括抓取的流量、主动测试的流量，方便后续溯源
  2. 目标说明书编写，了解测试系统的业务、功能、架构
  3. 严格限制测试范围
  4. 禁止破坏性操作
  5. 只关注有价值的漏洞
  6. 报告标准格式

Skill 设计​

基于上述梳理的规则，计划通过 yakit 来做日志留存，也方便发现漏洞的二次验证，那么只要让 AI Agent 在测试时遵循这些条条框框即可，那么最好的办法就是写一个 Skill 来约束 AI Agent 的行为。

请帮我编写一个渗透测试规范 Skill，当用户要求对网站进行渗透测试、SQL 注入测试、越权测试、SSRF 测试等安全测试工作时，调用此 Skill，Skill 需要包含如下内容，用于限制 Agent 的行为和输出：
1. 测试用浏览器（优先）、爬虫获取业务系统接口时的流量必须通过代理 http://127.0.0.1:8083，不开启系统代理；优先使用 Playwright 并配置代理，请求头强制携带 X-AI: {{date}} 标识，确保日志可追溯留存。
2. 识别测试目标的业务、功能和架构；若目标需要登录，可打开浏览器交由用户手动登录；每个功能测试完成后，在报告中对应勾选已测试的功能模块。
3. 仅允许对用户指定的域名及相关 JS 文件开展分析测试；若探测过程中关联到其他域名，必须暂停并向用户申请授权，获批后方可继续。
4. 所有涉及数据增、删、改的操作，以及可能影响业务可用性的测试动作，必须先向用户申请授权，获得明确同意后方可执行。
5. 仅关注可造成实际影响与危害的高危、严重级别漏洞，忽略无实质危害的低危及信息提示类问题。
6. 报告需包含功能模块和漏洞模块；漏洞模块中每条漏洞必须包含：漏洞标题、漏洞等级、漏洞 URL、漏洞说明、复现过程、修复建议。

使用方式​

主动扫描：

  1. 对 xxx 网站进行渗透测试。（按要求逐步测试，不保证效果）
  2. 对 xxx 网站进行渗透测试，允许测试关联的域名，目标是挖出 1 个高危漏洞。（激发潜能）
  3. 对 xxx.csv 中的网站列表进行分析，寻找你认为可能存在问题的网站进行测试。（随机性太高、不稳定）

被动扫描：

  1. 通过 yakit mcp 获取抓到的流量，并对这些流量进行测试，可以对关联的目标进行测试，目标是挖到3个高危严重漏洞。

注意事项​

  • 模型和 Agent 选择：最好选择模型厂商对应的 Agent，适配性会更高。
  • GitHub 上有大量的开源Skill，但大多数都是模型互相蒸馏、套娃复刻生成，思路高度固化，甚至限制了测试的 POC。这类 Skill 会锁死 AI 的发散思考能力，消解黑盒场景下未知探索的核心优势，难以挖掘非预期高危漏洞，实战中建议尽量规避使用。
